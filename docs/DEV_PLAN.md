## 2. Phase 3 변경 내역 (2026-09-07)

### 점검에서 발견한 결함과 조치

| # | 위치 | 문제 | 조치 |
|---|---|---|---|
| 1 | `data_service.DATA_FILE` | 상대경로여서 실행 위치(cwd)가 다르면 데이터 로드 실패 | `__file__` 기준 절대경로로 변경 |
| 2 | `prepare_features` | `df.dropna()`가 **전체 컬럼** 기준 → 선택 컬럼 결측 하나로 학습 행이 통째로 삭제될 위험 | `dropna(subset=FEATURE_COLUMNS+[target])`로 한정 |
| 3 | `model.generate_forecast` | `last_known['lag_3']`, `['lag_7']` 등 **존재하지 않는 컬럼 참조 + 미사용 변수** 잔존 | 죽은 코드 제거, 재귀 예측 로직으로 일원화 |
| 4 | Train/Holdout 분할 | `2026-07-06` 하드코딩 → 데이터가 바뀌면 Holdout 0건으로 400 오류 | 계획일 우선 적용 + 부족 시 **마지막 8주 자동 대체**(`split_mode` 노출) |
| 5 | `compute_wape` | ΣActual=0일 때 `0.0` 반환 → **오차 0(완벽)으로 오해** | `None` 반환, 화면은 `N/A` 표시 |
| 6 | 모델 비교 | Baseline이 Naive 1종뿐이라 계절성 비교 불가 | **Seasonal Naive(52주 lag)** 추가, 3종 지표 동시 반환 |
| 7 | 데이터 검증 | 계약 위반(중복·음수·날짜오류) 미검증 | `load_data`에서 검증 후 `DataError` |
| 8 | 통계 리포트 | Plan 요구(평균·표준편차·최근 4/8/12주·CV) 미구현 | `build_statistics` 신설 + 화면 표 추가 |
| 9 | 화면 | 모델 성능 비교표·통계표·Lead Time KPI 부재 | `index.html`/`app.js`에 추가, `null` 지표 방어 |
| 10 | 테스트 | 테스트 코드 자체가 없음 | `tests/test_forecast.py` 17건 신설 |
| 11 | 성능 | 요청마다 엑셀 재로딩 | `lru_cache`로 1회 로드 |

| # | 심각도 | 증상 | 원인 | 조치 |

## 4. 알려진 한계 (시연 시 그대로 설명)

1. **Holdout 지표는 1-step-ahead** 기준이다. 실제 4/8/12주 재귀 예측의 오차는 이보다 크다.
2. **간헐 수요 부품(MAT-1005)**은 세 모델 모두 WAPE 0.7 이상 — 주간 단위 예측이 부적합한 구간이다.
3. ML이 항상 Baseline보다 낫지 않다(5개 중 2개만 우수). 이는 설계된 정직성 규칙에 따른 표시다.
4. 데이터는 합성 데이터이며, 실제 도입 시 결측·리드타임 변동·단종 이력 등 추가 검증이 필요하다.
